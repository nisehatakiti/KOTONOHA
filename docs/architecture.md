# KOTONOHA — Architecture v0.1

## 1. 全体構成

KOTONOHAは、スマートフォンアプリとConoHa WING上のバックエンドで構成する。

```text
Flutterスマートフォンアプリ
        │
        │ HTTPS / JSON / 画像アップロード
        ▼
ConoHa WING
 ├─ API
 │   └─ PHP
 ├─ Database
 │   └─ MySQL
 ├─ 管理画面
 │   └─ PHPベースのWeb管理画面
 └─ 写真ストレージ
     └─ 縮小・圧縮済み画像
```

## 2. Flutterアプリ

スマートフォン側はFlutterで開発する。

主な役割:

- 地図表示
- 現在地取得
- 手動による地図更新
- アプリ内カメラによる撮影
- 写真の縮小・圧縮
- 言葉の入力
- 言の葉の閲覧
- 言葉を繋ぐ
- 通報
- 広告バナー表示

## 3. ConoHa WING

ConoHa WING側には、以下を配置する。

### API

スマートフォンアプリからのリクエストを受け付ける。

主な機能:

- 現在地周辺の言の葉取得
- 言の葉の新規登録
- 言葉の追加
- 言の葉詳細取得
- 通報登録
- 距離条件のサーバー側検証
- 5分間の新規投稿制限
- block_listによる利用制限

### Database

MySQLを使用する。

v0.1の主要テーブル:

- `kotonoha`
- `reports`
- `block_list`

### 管理画面

管理者専用のWeb管理画面をConoHa WING上に配置する。

主な用途:

- 通報一覧の確認
- 通報対象の言の葉確認
- 通報への対応結果登録
- 言の葉の非表示・削除
- block_listの確認・追加・解除

一般利用者向けの機能とは分離する。

## 4. 写真保存

写真はアプリ側で縮小・圧縮してからサーバーへ送信する。

元画像は保存しない。

サーバー上では写真ファイルを保存し、`kotonoha.photo_path`から参照する。

## 5. 位置情報

アプリは位置情報をリアルタイムにサーバーへ送信しない。

「地図を更新」を実行した時点で現在地を取得し、周辺の言の葉を取得する。

「言の葉を置く」を実行する場合は、投稿処理の直前に必ず現在地を再取得する。

距離による権限判定はサーバー側でも実施する。

- 半径5km以内: 地図上の存在表示
- 半径10m以内: 内容閲覧
- 半径5m以内: 言葉を繋ぐ

## 6. 管理者権限

v0.1では一般ユーザーアカウントを作成しない。

管理画面は管理者だけが利用できる認証付きWeb画面とする。

管理者は通報内容を確認し、必要に応じて言の葉を非表示・削除し、installation_idをblock_listへ追加できる。

## 7. 将来の拡張

v0.1では構成を単純に保つ。利用者・投稿数が増えた場合に、API分離、地理空間検索、画像ストレージ分離、管理機能強化等を検討する。
